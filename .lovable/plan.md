# Shared voice library + free-voice fallback

## Goal
Each spoken line should be generated by ElevenLabs **once, ever** — then shared with every device — instead of each device paying for its own copy. When credits run out, the app keeps working on the free built-in device voice.

## Changes

### 1. Shared voice clip storage (backend)
- New `voice_clips` table: key = hash of (text + language), value = audio file stored in backend storage.
- Enable RLS with public read (audio only, no personal data) and server-only write.
- New storage bucket `voice-clips` (public read).

### 2. Server-side check-before-generate (`src/lib/tts.functions.ts`)
- On a voice request: look up the shared library first.
  - **Hit** → return the stored audio (no ElevenLabs call, no credits).
  - **Miss** → call ElevenLabs, save the result to the shared library, return it. Only the very first request for a line ever spends credits.
- On ElevenLabs `quota_exceeded` (or any failure): return a clear "unavailable" signal instead of an error, so the client falls back quietly.

### 3. Client behavior (`src/lib/speech.ts`)
- Keep the per-device cache as-is (instant replay, works offline).
- When the server says the voice is unavailable (out of credits), use the device's built-in voice for the rest of the session and stop asking the server — already in place, keep it.
- No change to the child-facing experience; narration always works either way.

### 4. Optional: pre-generate common lines once
- After the shared library exists, pre-warming common lines happens **once globally** (first device to ask), not per device — no code change needed beyond the above.

## Result
- Refilling ElevenLabs credits buys you a growing permanent library; over time, credit usage drops toward zero because nearly every line is already recorded.
- New devices, reinstalls, and cleared data no longer re-spend credits.
- Empty credit balance never breaks the app — kids hear the free device voice until you refill.

## Technical notes
- Backend = Lovable Cloud table + storage bucket; access via server function only for writes.
- Cache key: SHA-256 of normalized text + locale.
- Migration includes GRANTs and RLS per project rules.
